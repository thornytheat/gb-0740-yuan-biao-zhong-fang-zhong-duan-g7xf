# 数据字典

| 字段 | 含义 | 约束 |
|---|---|---|
| `datasets[].id`, `revision` | 数据集和变换修订 | ASCII 字母、数字、下划线和短横，保留前导零；每数据集至多 12 条输入边。 |
| `datasets[].inputs[].dataset`, `lag` | 上游名与读取时差 | 当下游日为 D 时读取 `D−lag`；天数 0–7。依赖图须无环。 |
| `heads[].dataset`, `day`, `version`, `rows` | 当前分区指针及行数 | 分区由 `dataset@YYYY-MM-DD` 标识。当前快照每分区唯一。 |
| `changes[].version`, `previous`, `rows` | 源分区的新版本、预计当前版本、行数 | `previous=null` 代表期望新增。仅源表可登记直接变更。兼容旧 `count` 字段。 |
| `through` | 分区截止日 | 包含该日期，从最早受影响输入向下游传播，不触及截止之后的分区。每条变更回溯最多 31 日。 |

相同变更的重传计为重复。相同分区的候选版本或行数打架时全部隔离，保留行号。每个分区先计算最终应读哪些快照，按数据集拓扑序再按分区日排列。已阻断的计划不会被依赖者误当作有效输入，窗口内未受影响的依赖可复用当前快照。

新版本由下游数据集、规则修订、分区日和排序后的输入版本及行数共同计算 SHA-256。演示数据集执行拼接，各读入分区行数相加。数值使用整数，超出 JSON 常见安全整数范围的汇总或派生数按字符串输出。

写入演练先核验每个待写指针，再一次性生成新视图。回滚先核验仍持有演练发布版本，再逐项恢复原指针，新增分区则移除。任一指针陈旧时整组拒绝。该过程作用于清单中的副本，实际仓库的调度与执行另由值班系统负责。

受影响分区 = 待写 + 复用 + 阻断。输入行数 = 采信 + 隔离 + 重复。写入后的行数 = 原行数 + 待写分区行数增量。阻断保留原快照行数。批次绑定原始字节和规则版本，文件大小至多 300 KiB。

## 隔离解除凭证

| 字段 | 含义 | 约束 |
|---|---|---|
| 故障报告 `plan` | 凭证所属的重放计划编号 | 计划须已签发，且含依赖图与现行指针。 |
| 故障报告 `partition` | 校验异常的源表分区 | `dataset@YYYY-MM-DD`，须为无读取边的源表且有现行指针，不晚于计划截止日。 |
| 故障报告 `evidence` | 原异常证据 | 含 `detector`、`detected`（ISO 8601）、`expected`、`observed`；期望与实测须不同。证据单独存放，凭证只钉其摘要。 |
| 故障报告 `repairs` | 针对异常分区的修复快照 | 至多 300 条且分区须等于异常分区；`checksum` 与证据期望一致才可作为解除依据。 |
| 凭证 `冻结边界` | 异常分区及其多跳下游 | 从异常源分区沿反向依赖 BFS，记录每个分区的跳数与经自分区；边界外分区继续产出。 |
| 凭证 `解除` | 每条可解除分区及其依据 | 源分区凭修复校验值（`REPAIR_VERIFIED`），下游按拓扑凭上游处置结果重算（`RECOMPUTE`），各带当前与目标版本。 |
| 凭证 `保持冻结` | 仍不能恢复的分支 | 原因码：`NO_REPAIR` 无修复快照、`REPAIR_MISMATCH` 修复校验值不符、`UPSTREAM_FROZEN` 上游仍未解除、`MISSING_INPUT` 非冻结上游缺快照。 |
| 凭证 `冻结前快照` | 边界内各分区的冻结前版本 | 解除失败时按此恢复旧版结果；无指针的分区记为 null，恢复时移除。 |

凭证编号由规则版本、计划编号与故障内容共同哈希，同一故障重试复用原凭证。发布（`POST /api/quarantine/credential/{id}/release`）、补数（`GET .../backfill`）、回查（`GET .../review`）读取同一份凭证。解除演练先核验现行指针仍等于冻结前快照，任一不符即整组恢复冻结前旧版结果再以 `STALE_HEAD` 报失败。回查须读到原异常证据且摘要一致，证据删除或被替换时已解除范围无法复核。
